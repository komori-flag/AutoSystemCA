AutoSystemCA v2.0

开机自动系统 CA 注入模块 · 安全架构

使用流程

  1. 把原始证书放入
    /data/adb/modules/auto_system_ca/certs/（原文件保留）
  2. 设备有 openssl：直接重启，开机自动转换并注入
  3. 设备无 openssl：点模块的「执行」（Termux 可先 pkg install openssl-tool），转换产物输出到 converted/；或放入电脑预转换的 <hash>.0 文件
  4. v2.0 的「执行」会注入运行中的进程（nsenter），无需重启即刻生效

转换来源映射：cat .../converted/mapping.txt（格式 hash.n|原始文件名）

注入模式（config 文件）

模式说明
tmpfs（默认）内存 tmpfs 挂载到 apex 路径并锁定只读；mount 表无 /data 特征（检测对抗）
passive零挂载绝对安全；证书只写入模块目录，需框架挂载才生效

SYNC_SYSTEM=1：证书不生效的个别 ROM（framework 读 system 真实目录）可开启。

检查注入是否成功

cat /data/adb/modules/auto_system_ca/last-run.log

mount | grep cacerts → 应显示 tmpfs 挂载（而非 /data）

ls -Z /apex/com.android.conscrypt/cacerts/ | grep 你的hash → 标签应为 system_security_cacerts_file

看到 ABORT 表示 fail-safe 中止（副本不完整，未做任何挂载）——检查 certs/ 与 converted/ 内容。

检测对抗（KSU 策略反转）

  • KSU 设置 → 启用「默认卸载模块」：未授权应用（检测/银行类）纯净沙盒，无挂载痕迹
  • 为抓包工具（AdGuard/浏览器）单独开启「保留模块挂载」：只有它们看到证书
  • 配合 LSPosed 隐藏应用列表隐藏 root 工具
  • 敏感时期可 config 切 passive（零挂载）
